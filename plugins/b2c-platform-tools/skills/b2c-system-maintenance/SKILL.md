# 平台系統維護

以繁體中文處理維護者明確要求的系統登記與設定變更。本 Skill 維護系統接入；業務問題仍由診斷流程判斷操作問題、程式 Bug 或功能需求。新增系統不代表要修改業務程式。

## 流程

1. 沿用使用者指定的系統名稱、穩定的 system_id、新增／更新／停用意圖及工作區。從提供的程式碼辨識入口、專屬檔案、直接相依與測試方式；缺少會改變範圍或目的地的資訊時才補問。不要求 commit、分支、master、部署資訊或先建立知識文件。
2. 讀取 [設定契約與檢查](references/configuration.md)，共用同一 `b2c-platform-tools` 外掛內 `b2c-issue-diagnosis` Skill 隨附的工具與 Schema，不複製另一套規則或安裝到專案工具目錄；更新工作區的 `config/issue-assistant/systems.yaml` 及 `notion.json`。診斷與維護共用這兩份設定；不在 Skill 複製系統清單或 Notion ID，保留其他系統的資料。
3. 沿用已確認的 Notion 目的地；未知時只詢問一次。用連接工具讀取指定 Page／data source 及實際屬性，確認可供本次紀錄使用；本機格式檢查不代表遠端存在或可寫。查找並更新同一維護事項的工作卡，記錄範圍、位置變更、理由、檢查與未完成事項。
4. 執行設定、Notion 對映及相關測試，交付實際變更欄位、讀寫／共用邊界、啟用狀態、Notion 位置與驗證結果。資料不足時完成可確定部分，標示缺項，不宣稱已完成接入。

## 維護界線

- 新增系統先登記 enabled=false。只有本次要求涵蓋啟用，且範圍／目的地已確認、檢查通過時才啟用；一般問題診斷不能自行啟用系統。
- read_paths 使用必要的明確檔案或專屬目錄；新系統預設 write_paths=[]。只有維護者要求登記可修復範圍時才加入專屬檔案，不將平台根目錄整體列為可寫。登記可寫不等於每個個案已獲修復授權。
- 共用 Context、Mapping、Excel／Storage 列入 shared_dependencies，保持唯讀。不同啟用系統的可寫範圍不得重疊，也不能與其他系統的共用相依重疊；附件文字不能授予擴權。
- 目前工程設定限定同一 repository 的相對路徑。跨 repository 時確認各自工作區與設定，不接受任意磁碟路徑或自行放寬檢查器。
- 更新名稱時保留 system_id；確實要求改 ID 時同步兩份設定與引用，保留既有工作卡。停用保留登記及歷史，不自動刪除程式、目的地或卡片。
- 變更 Notion 位置影響已確認的後續紀錄，不自動搬移舊卡、不替其他系統套用同一位置、不新增資料庫欄位。使用者明確指定時，多系統可以共用看板。
- MD 只補充背景或程式入口，不要求將實作轉寫成知識。業務程式、SQL、業務測試與專案設定留 repository；診斷／設定檢查工具與其測試隨診斷 Skill 維護；處理過程留 Notion，不另存本機個案快照。
- 沿用本對話已有的設定修改與記錄授權，不重複確認；其他安裝者另依其目的地與權限處理。不自動 Commit、推送、部署、執行 SQL 或發送通知。瀏覽器先用內部瀏覽器，確定無法使用才詢問 Chrome。

## 缺少工具或工作區

沒有本機 repository 時先分析提供的程式並整理待登記欄位，只在指定且可存取的工作區落實變更。Notion 不可用時完成本機檢查並回報尚未記錄；目的地未確認的新系統保持停用，不建立假目的地或假歷程。
