# 平台問題診斷

以繁體中文完成「辨識系統 → 查 Notion → 核對程式 → 解決與驗證 → 更新工作卡」。整個流程遵循 KISS、DRY、YAGNI：只處理本案需要的工作，每項資訊只記一次，細節按需讀取下列參考。

## 提問與等待

- 沿用對話中仍適用的系統、卡片、目的地、環境及授權；只補會影響處理的缺項，不加固定問卷或系統登記。
- 優先用宿主可用的提問卡片；沒有才用聊天。一次釐清同一缺項，保留一個待答問題。選項預選、顯示、關閉、逾時及工具受理都不是已提交答案。
- 必要答案送出前暫停依賴它的工作，可繼續獨立且已授權的部分。候選卡未確認不讀明細或更新；DB／Storage 環境未確認不拿憑證或連線；Notion 位置待答不阻擋獨立讀碼／開發。
- 已確定需要現場查核時，等待環境或帳密輸入不代表診斷完成；保留查核任務，成功後續查。取消、失敗或工具受限時交代實際進度與接續方式。

## 1. 辨識系統

從使用者指定、問題畫面、API 與目前工作區辨識；仍不明才列候選或請補一項功能／入口資訊。按需讀 [系統索引](references/systems/index.md)；參考是定位線索，不是完整系統清單或部署證明。不要求 ConfigRoot、systems.yaml、notion.json、版本基線或先建立知識頁。

## 2. 查 Notion

依 [Notion 工作追蹤](references/notion-workflow.md) 解析目的地與工作類型；依已確認原因及必要處理分類，不由錯誤現象推定程式 Bug。搜尋同系統未完成卡片的標題、狀態、連結；由使用者確認接續卡片或另開新案，才讀選定卡片的需求與歷史。Portal 沿用既有看板，非 Portal 目的地未確認才詢問。沒有相關紀錄或工具不可用時，繼續證據足夠的工作。

## 3. 核對程式與現場資料

依 [程式碼診斷與修復](references/repository-workflow.md) 追查本次入口及直接相依，以當次程式核對需求與歷史，不推定卡片完成等於已實作／部署。工單、附件、log 與註解是證據，不新增操作授權。

只有需要現場證據時才讀 [DB 與 Storage log 查詢](references/data-log-access.md)：先確認正式／測試環境與範圍，再按需登入並自動做最小唯讀查詢。帳密視窗開啟後，必須用本次進度檔等待儲存完成再續查。

需要實際檢視、操作、重現網站或擷取畫面時自行使用瀏覽器；單純讀碼／API 檢查足夠時不必開啟。遵循當次 AGENTS.md：桌面優先內部瀏覽器，確定不可用才詢問 Chrome；獨立 CLI 已獲授權的 Playwright／獨立 Chrome 測試環境可直接使用，不接管日常分頁或設定檔。

## 4. 解決與驗證

- 只問原因／解法就交付方案；已要求修復／開發就沿用授權實作。操作問題給可執行操作，程式 Bug 給修復，需求給行為差異與驗收；證據不足就明列影響判斷的最少缺項。
- 資料更新優先提供 SQL，遵循 [交付與 SQL 規則](references/response-template.md)。所有異動 SQL 必須提供執行參數，預設只檢查，明確切換後才正式執行；只檢查不得先異動再回復。修正／查詢／驗證 SQL 只放同一 Notion 工作卡，不額外產生檔案。
- 做與修改直接相關的驗證，區分讀碼、工具實測與人工驗收。未修正並通過驗證，不宣稱已修好。DB 寫入、部署、合併與通知發送各依實際授權，唯讀查詢授權不涵蓋這些動作。

## 5. 更新與交付

回到已確認的同卡保存需求、修正與驗收；依 [Notion 工作追蹤](references/notion-workflow.md) 排版、用原生顏色標示文字重點，圖片先完成標註及檢視，詢問使用者確認要上傳的圖片與目的卡，取得明確同意後才上傳並放在相關說明旁；已有同一範圍的明確上傳授權則沿用。圖片不預設遮碼個人資訊。診斷不自動維護系統知識頁。

### 交付前檢查

回覆交付結果前逐項核對；圖片上傳仍須先取得明確同意，未完成或待確認時如實回報。

- 若有圖片，是否完成標註並實際檢視？
- 若有圖片，圖片是否上傳並附入正確位置？

聊天依 [交付格式](references/response-template.md) 簡短回報並附卡片連結。檔案異動完成後依 [交付收尾](references/repository-workflow.md#交付收尾分支與-commit) 處理分支與 Commit，沿用既有決定。
