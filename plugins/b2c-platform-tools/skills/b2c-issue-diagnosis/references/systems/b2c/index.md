# B2C 系統資料

本外掛適用 B2C 平台內所有系統／功能模組，系統設定識別碼統一為 `b2c`。Portal／PortalAPI 是預設程式來源，功能索引與模組資料夾不是支援清單。共用流程位於 [common](../../common/initialization.md)，本資料夾維護 B2C 的來源與定位線索。B2C 以外的獨立系統需要隨附資料時，才另建同層系統資料夾，不共用 B2C 憑證。

## 問題定位

已有文件、API 或檔案線索時直接讀相關來源；需要按功能找入口才讀 [功能與文件索引](functions.md)，再讀本案模組的 `<模組>/index.md`。已盤點的 32 個模組使用相同入口格式，包含既有文件、前後端入口、相依或中介線索與核對限制。追請求時讀 [前後端入口對照](entry-map.md)，涉及跨模組問題才讀 [共用機制](shared-mechanisms.md)，不必每次載入全部模組文件。

未列索引的 B2C 功能照常由頁面、API、選單或程式符號追查；缺少會影響定位的資訊才補問，不因沒有模組文件而停止。所有模組適用相同的文件補充原則，參考資料只提供該模組線索，不改變其他模組的可用範圍。

文件中的路徑縮寫：`Portal:`／`PortalAPI:` 代表各自儲存庫根目錄；`V/`＝Portal 的 `Portal_Net5/PortalVue/`；`A/`＝PortalAPI 的 `PortalAPI_Net5/`。搭配本機設定定位，不保存維護者的絕對路徑。程式檔名／方法只作入口，實際判斷須讀當次版本。

## 預設專案來源

唯一機器可讀來源為 [system.json](system.json)：前端 `Portal`、後端 `PortalAPI`，網址由使用者明確提供。初始化直接從該檔顯示對應網址，本機路徑另外詢問各安裝者；不從 Skill 安裝位置、維護者電腦或遠端網址推算路徑。

- [前端定位](frontend.md)：需讀前端程式時使用。
- [後端定位](backend.md)：需追查 API／資料存取時使用。
- [Notion 目的地](notion.md)：解析 B2C 工作看板或明確要求維護的系統知識位置。
- [資料來源與憑證](data-access.md)：B2C Blob log 的 NLog 候選、來源核對與 DB／既有 Storage 憑證對應；登入及查詢依共用流程。

套件資料隨外掛版本維護；日常個案與知識保存規則依共用流程，不自動修改安裝快取。歷史參考不是當次程式／部署證明。

## 何時補模組資料

已盤點模組各用一份短 `index.md`，主功能表只維護名稱／別名、連結與入口狀態。補新模組時先連到既有文件與入口；PMForecast 也遵循同樣格式，既有規則與邊界已整合進該模組入口，不要求固定產生 scope／knowledge 兩份檔案。

內容取捨依 [共用原則](../../common/system-maintenance.md#隨附索引的取捨)。特殊規則保留來源，未確認事項標示限制；通用流程引用共用文件。模組沿用 B2C 路徑，沒有索引的功能仍可直接分析。只有明確維護外掛來源時才改隨附索引，日常知識保存依共用維護流程。
