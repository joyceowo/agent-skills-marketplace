# 共用初始化與缺項詢問

本流程只負責設定與定位；系統的預設儲存庫、憑證對應及專屬規則讀取 `references/systems/<system>/`，不在共用流程維護第二份。B2C 入口見 [系統索引](../systems/b2c/index.md)。

## 保存位置與工具

- 使用 [settings.py](../../scripts/settings.py)，Python 3.10 以上，僅需標準函式庫。以下 `<診斷技能目錄>` 是實際安裝的 b2c-issue-diagnosis 目錄，不是本機業務程式路徑。
- 本機路徑保存於 `~/.local/share/b2c-diagnostics/settings.json`；更新／重新安裝外掛不會覆寫。格式為 `{"version":1,"systems":{"b2c":{"frontend_path":"本機絕對路徑","backend_path":"本機絕對路徑"}}}`，兩個路徑都可缺省。這是格式示意，不能直接當設定寫入。
- `settings.json` 只保存路徑，保留原 v1 格式；Azure Blob 非秘密來源另存 [blob-sources.json](azure-blob-logs.md#來源與狀態)。DB／既有憑證只存 OS 保管庫，Azure 登入交由 Azure CLI 管理；不把帳密、含秘密連線字串或 token 放入上述設定、命令列、聊天、Git 或安裝快取。專案來源網址由套件的 `system.json` 提供，不要求使用者重填。
- 工具不搜尋整機目錄、不存取憑證、不 clone／pull、不驗證遠端登入。ready 只代表目錄存在且可讀；不代表來源身分、可寫權限、依賴可用、建置通過或已部署。

## 主動初始化

使用者要求初始化／設定時，先 `status --system <系統>`，列已設定與缺少項目。接著用提問卡片選本次項目：「前後端路徑」「DB 登入」「Blob log（可稍後）」；DB／Blob 再沿用已指定環境，未知才問測試或正式。使用者已指定項目就直接接續，不重問。可部分完成、略過其餘項目；沒有單一全有或全無的初始化門檻。

路徑設定一次詢問一個缺項：請提供前端或後端已下載的本機資料夾，並說明對應預設來源。兩者可以位於不同儲存庫，也可使用已確認的同一工作區內不同目錄；不依資料夾名稱猜測來源。如果只提供遠端網址，保留為來源線索，繼續詢問本機路徑，不把網址存為路徑或自動下載。

檢查目錄後，按需讀取該路徑適用的 AGENTS.md、README 及 Git 來源等最少資訊，核對前後端身分；Git 來源可能含秘密，只比較必要來源，不原樣輸出含憑證的 URL。來源與預設不符時先指出差異，確認這是本次預期的替代來源；不擅自切分支／更換 remote。資料夾不可讀、路徑失效或宿主未授權存取時，說明實際原因並補正，不繞過權限。

使用者已要求保存的有效路徑，執行 `set-path` 後回讀狀態；只修改該系統該角色，保留其他設定。原設定檔損壞／未知版本時停止寫入，回報錯誤，不以空白資料覆蓋。要求更換既有路徑時只更新明確指定的項目；要求移除時才 `clear-path`。

## 日常使用時缺少設定

只有本次需要讀程式時才解析對應角色的路徑；只查工作卡、討論方案或處理已提供片段，不要求先完成初始化。

解析優先順序：本次明確指定的路徑 → 已保存的同系統路徑 → 已確認屬於本次系統與角色的目前工作區。暫用路徑不覆寫保存值；目前工作區尚未確認身分時，不直接把 cwd 當前端或後端。

執行 `resolve --system <系統> --role frontend|backend`，有本次明確路徑加 `--path`，有已確認工作區才加 `--workspace`。工具回 `needs_input=true`／exit 2 表示缺少或失效；設定檔讀取錯誤為 exit 1，不當成從未設定。已保存路徑失效時先提示更新，不默默改用其他來源。

缺項時實際送出提問卡片，例如：

> 本次需要讀取後端程式，目前尚未設定路徑（或原路徑已失效）。要如何處理？
>
> - 設定並保存後端路徑
> - 本次提供路徑，不保存
> - 暫不設定

選擇前兩項後才詢問尚缺的本機路徑，已有可用路徑就不重問。選保存才執行 `set-path`；選暫用則以 `resolve --path` 驗證，不寫檔。使用者直接表示「這次用此路徑並記住」等已涵蓋選擇時沿用，不再問同意。

提問的預選、顯示、關閉及逾時都不是答案。必要答案未提交前不做依賴工作，也不重送同一問題；可繼續獨立且已授權的部分。取消／暫不設定時，僅暫停需要該設定的部分並交代缺少的查核，不能宣稱完整診斷完成；同次任務未改變決定就不再催問。設定成功後直接接續原任務。

DB／既有憑證只補本次需要的一筆：先確認環境與資源，缺憑證時詢問是否設定；明確選擇設定後才開安全輸入視窗。使用者已授權設定該筆就沿用；拒絕時不開窗、不取用別的環境，依 [資料存取](data-log-access.md) 暫停該連線。

Azure Blob log 使用 [來源與登入流程](azure-blob-logs.md)：來源缺少才詢問設定；已保存則檢查本次租戶與登入，有可用登入就沿用，需重新驗證才詢問登入。初始化保存來源後可選「現在登入並檢查讀取／稍後」；僅前者做最小遠端驗證。完成後直接續接原查詢；略過只影響 log 查核。來源保存、登入可用及讀取已驗證須分項回報，不能由其中之一推定另外兩項。

## 命令與結果

以下以 B2C 為例；路徑由使用者提供，正式執行時將示意值替換為已確認值。PowerShell：

```powershell
python -I '<診斷技能目錄>/scripts/settings.py' status --system b2c
python -I '<診斷技能目錄>/scripts/settings.py' set-path --system b2c --role frontend --path 'C:/work/Portal'
python -I '<診斷技能目錄>/scripts/settings.py' resolve --system b2c --role backend
python -I '<診斷技能目錄>/scripts/settings.py' resolve --system b2c --role backend --path 'C:/work/PortalAPI'
python -I '<診斷技能目錄>/scripts/settings.py' clear-path --system b2c --role frontend
```

macOS 使用 `python3` 與實際本機絕對路徑，其餘參數相同。已有可用 Python 環境就沿用，不為路徑設定安裝 keyring。

- `status` 可加 `--role`，只檢查本次需要的前端或後端；不因另一項缺少阻擋已就緒的角色。
- exit 0：所選目錄可讀／儲存成功，或移除設定成功；exit 2：所選路徑缺少／失效；exit 1：操作或設定格式錯誤；exit 130：取消。
- `--settings-file <絕對路徑>` 只用於使用者指定位置或隔離測試；不同命令必須沿用同一位置，不自動建立其他副本。
- 一次只執行一筆設定異動；不平行執行 set-path／clear-path。路徑設定不會擴大檔案寫入、遠端存取或其他操作授權。
