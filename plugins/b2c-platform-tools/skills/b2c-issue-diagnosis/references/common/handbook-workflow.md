# 維運手冊：查用與自動維護

一筆是一份跨案件可重用的「常見問題」或「權限申請」手冊。工作卡保留個案，手冊保留人工能照做的判斷與步驟；既有業務規則只連結到其來源，不複製第二份。其他系統知識仍依 [系統知識維護](system-maintenance.md) 明確啟動。

## 目的地與設定

使用 [handbooks.py](../../scripts/handbooks.py)，Python 3.10 以上、只需標準函式庫。設定保存在 `~/.local/share/b2c-diagnostics/handbooks.json`，與只保存路徑的 `settings.json` 分開；更新／重新安裝外掛保留設定。檔案只存各系統的父頁 ID、資料庫 ID、`collection://` data source、`auto_maintain` 與 `types`，不存 Notion token、帳密、個案內容或宿主連接 ID。

1. 已辨識系統且需要處理問題／權限申請時，執行 `status --system <系統>`。有目的地就使用目前有權限的 Notion 連接讀取父頁、資料庫與 schema，核對父子關係及資料來源；不得只因名稱相同就換位置。保存成功只代表設定存在，`remote_access=not_checked` 不代表遠端可讀／可寫。
2. 本次明確指定的目的地與自動維護決定優先；暫用不覆寫保存值。首次保存或更換位置時，先讀取已指定頁面與其資料來源，再依使用者實際決定保存目的地、開關與類型。明確要求啟用後直接設定，不重問；只有提供連結不等於啟用。
3. 缺設定且沒有本次目的地時，依 [初始化](initialization.md) 詢問「設定並保存／本次使用、不保存／暫不設定」。缺失不阻擋獨立診斷；暫不設定或停用後不逐案催問。設定損壞／未知版本應報錯，不當成首次使用，不覆寫空白設定。
4. 私人位置不寫入 Skill、`system.json` 或共用市集。B2C 模組沿用 `--system b2c`；其他系統不得套用 B2C 設定。已保存位置失去權限、被刪除或歸屬不符時停止該處同步，保留設定並回報，不擅自換連接／目的地、重建資料庫或調整權限。

命令中的 ID 均須替換成當次讀取且已確認的值；`set` 必須明確指定開關。類型 `common-issue`＝常見問題，`access-request`＝權限申請；可只選其中一種。

```powershell
python -I '<診斷技能目錄>/scripts/handbooks.py' status --system b2c
python -I '<診斷技能目錄>/scripts/handbooks.py' set --system b2c --page-id '<父頁UUID>' --database-id '<資料庫UUID>' --data-source-url 'collection://<資料來源UUID>' --auto-maintain on --types common-issue access-request
python -I '<診斷技能目錄>/scripts/handbooks.py' disable --system b2c
python -I '<診斷技能目錄>/scripts/handbooks.py' clear --system b2c
```

macOS 使用 `python3`。`disable` 保留位置並關閉自動維護，`clear` 只移除該系統設定；不刪 Notion 內容。`status`／`disable` 缺設定回 exit 2、不建立檔案；成功回 0、錯誤回 1、取消回 130。`--config-file <絕對路徑>` 僅用於使用者指定位置或隔離測試，各命令沿用同一檔案；設定寫入依序執行，不平行修改同檔。

## 處理前查用

- 有已確認目的地即可搜尋，不要求啟用自動寫入；沿用宿主 Notion 工具，先讀實際 schema，再按系統／模組、類型、現象／錯誤訊息及操作別名找候選。搜尋被截斷或未完成分頁時，不宣稱不存在；建立前須完成足以排除同類候選的查找。
- 優先查「可使用」，也核對相關「草稿／待更新／已停用」以避免重建；後三者只作線索，不當作已驗證指引。手冊可在已確認範圍直接讀取，不套用工作卡的逐張選卡確認；來源工單仍遵循 [卡片確認限制](notion-workflow.md)，不得藉手冊連結擴讀未選定／已完成工單。
- 核對環境、版本、資料範圍、必要條件及本次現象，再採用步驟；同一現象不等於同一原因，條件不符則接續正常診斷。手冊不免除本次必要讀碼、現場查核或驗證。
- 權限申請先核對申請對象、角色／操作能力、資料範圍、環境、用途、期間與本次核准；規則明確時按流程處理，不強制做故障排查。設定後行為仍不符才進入診斷。

## 收尾時新增、更新或略過

只有本次明確要求維護，或有效設定的 `auto_maintain=true` 且類型在 `types` 內時才寫入；後者不逐案重問文字收錄。使用者本次要求不寫入或停用時優先遵從。自動化在本次技能執行中完成，不是背景排程；人工稍後在 Notion 勾選驗收，須再次執行時讀取該卡、確認證據後才補同步，不承諾自動監控。

| 本次內容／證據 | 動作與狀態 |
| --- | --- |
| 新的可重用判斷／流程，操作與必要驗證已確認 | 新增「可使用」，註明實際驗證環境、版本及範圍；首次出現也可收錄。 |
| 有具體可重用步驟，但仍缺必要實測或人工驗收 | 有保存價值才新增「草稿」，將待驗證步驟與缺項寫清楚；不填造驗證日期。 |
| 只有假說、單次數值修正或未核對的歷史說法 | 留在本案，不建立可供照做的手冊。 |
| 既有手冊完全適用且沒有新內容 | 沿用並連結，不新增、重抄來源／歷程或無故刷新驗證日期。 |
| 同原因與處理方式，但有已確認的新條件、步驟或例外 | 在原手冊局部整併，保留人工內容；新增部分未驗證且影響操作時標「待更新」。 |
| 同現象、不同原因 | 補可區分原因的判斷分支；不同處理流程確有必要才拆篇。 |
| 草稿取得原缺少的驗證證據 | 核對原待驗證項目後補結果，條件齊備才轉「可使用」。 |
| 與業務規則、核准流程或人工修訂衝突 | 保留原結論與新證據，標「待更新」並提出差異，不自動決定新業務規則。 |
| 人工標示「已停用」 | 保留停用，不自動重新啟用；有替代手冊時連到其來源。 |

去重比對系統／模組、原因或申請項目、適用條件、處理方式，不能只比標題。寫入前重讀候選最新內容，保留人工維護人、勾選、依據與歷史；只修本次差異，不整頁覆寫。工具逾時或結果不明時先核對回傳 ID／目的地及同類候選，確認未完成才重試缺少部分；無法確認就回報待同步，不盲目再建一篇。一般維護不新增／改名欄位、選項、檢視或範本；首次建置另依使用者授權。

## 人工與 AI 共用格式

沿用實際 schema 與既有範本。新建手冊資料庫時，一筆是一篇手冊，基本欄位為名稱、類型（常見問題／權限申請）、系統／模組、狀態（草稿／可使用／待更新／已停用）、維護人、最近驗證日期。維護人未知不填；最近驗證日期只取與本手冊內容直接相關的實際成功驗證，採使用者時區，不用本次寫入日期或案件完成狀態代替。

| 類型 | 本文必要內容 |
| --- | --- |
| 常見問題 | 使用者會搜尋的現象／別名；適用系統、環境與版本；區分原因的檢查與預期結果；處理入口、必要輸入及步驟；完成驗證；停止／轉交條件與已知窗口。 |
| 權限申請 | 可申請角色／能力及對象；必要申請資料；已確認的核准角色與條件；設定入口、步驟及預期結果；生效驗證、撤銷／到期處理及失敗轉交。 |

每篇附來源工作卡／規則連結及 [證據分類](system-maintenance.md#知識依據)。分別記錄讀碼、工具實測與人工確認；讀碼不代表部署或操作成功。欄位／步驟未知就標明缺項，不虛構窗口、角色或核准人。人工手冊寫業務與操作用語，程式入口只留必要依據。

個案帳號、單號、期間、實際核准及完整個案 SQL 留在工作卡，手冊保存共用條件並連回來源，不把整張工單複製成手冊。資料處理沿用 [SQL 交付與執行規則](response-template.md)，不因重用而複製舊值、擴大範圍或另產生 SQL 檔。手冊收錄權限不包含本次申請核准、DB 寫入、部署、通知或圖片上傳；圖片仍遵循 [圖片確認](notion-workflow.md#圖片標註與上傳)。

## 寫入驗證與交付

寫入後回讀實際頁面及必要屬性，核對適用條件、操作與預期結果、證據／狀態、來源連結、人工內容保存及是否重複；刪去不影響判斷、執行或驗證的重述。範本不能當成實際解決案例，檢視篩選不代表存取隔離。

聊天只摘要新增／更新／沿用的手冊連結；不值得收錄時不用列例行判斷流水帳。案件處理結果與手冊同步結果分開：無權限、失敗或無法回讀時回報「手冊尚未同步／驗證」，已完成的案件工作不因此改成未修復，也不把同步失敗寫成已保存。
