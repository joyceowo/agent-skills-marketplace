# 診斷交付

## 聊天與工作卡

聊天預設只寫簡短結論、實際處理狀態、必要的使用者動作及 Notion 同卡連結。本案必要的修正、SQL、查核結論與驗收留同卡；只有使用者要求展開或 Notion 無法同步時，才在對話補充必要內容並如實說明未同步部分，不另存檔案備援。

有查用或維護維運手冊時，併附本案相關的手冊連結及新增／更新／沿用結果；案件與手冊同步狀態分開回報，回讀失敗不宣稱已同步。共用步驟、去重與人工使用格式依 [手冊流程](handbook-workflow.md)，個案帳號、核准紀錄與完整 SQL 仍留同卡；既有核准、SQL 或手冊寫入授權不代替本次業務操作授權。

診斷開頭先讓讀者看懂哪裡錯、正確應如何，以及影響或觸發條件；必要證據與限制緊接相關結論，不讓讀者從查核過程自行找原因。Git 引入時間與 commit 連結在原因說明或處理歷程擇一保存；完整時間線只在比較版本會影響判斷時保留。

資訊只記一次：

- 分支、負責人、處理狀況等已有欄位的資訊，只留在欄位；正文僅在該值直接影響判斷、操作或驗收時補充必要差異，不重述目前值。
- 簡單修正以原因、實際修改及必要影響為主，通常各一句即可；SQL、跨系統條件或驗收差異按需要展開，不為填滿章節增加描述。
- 修正與合併的 commit 連結集中於處理歷程；不在正文另抄分支、完整雜湊、逐次提交時間或遠端核對結果。基底版本、合併過程及測試細節只有直接影響本案結果時才保留。

工作卡只保留與當次問題直接相關的需求、證據、原因、處理與驗收。每段都檢查「刪除後是否影響本案判斷、修改、執行或驗收」；不影響就省略。查核結果寫成支持判斷的必要結論，不列逐步搜尋、讀檔、工具呼叫、套件載入、測試嘗試或掃描筆數等查核流水帳；版本、範圍、環境及取值依據只在差異直接影響本案判斷時保留。Notion 正文及 SQL 不記錄 DB Server 名稱或位址，不加入 `ExpectedServer`、主機名稱檢查或回傳主機名稱的查詢（如 `@@SERVERNAME`、`SERVERPROPERTY('ServerName')`）；必要時保留目標資料庫檢查。此呈現限制不取代內部連線時的環境核對。工具阻礙在聊天說明，卡片只列需使用者處理的動作與影響，不堆疊保留語。

不列其他案件的排除說明、選卡過程或對話操作紀錄。查核時順帶發現、但尚未證明與本案有因果或必要處理關聯的缺陷及改善建議，不併入本案原因、處理清單、方案或 Git 歷史；使用者另行要求追查時再依該範圍處理。

程式已核對、現場查詢、使用者確認及假說必須分清楚；只保留本案必要證據與限制。Notion 的結構、色彩、圖片與人工結案統一依 [工作追蹤](notion-workflow.md)，不另套報告欄位。

## 方案選擇

- 依已確認的變動來源評估方案。DB／設定變動觸發問題時，評估修正來源或還原的可行做法，與程式修正比較；只列符合既定需求的選項，不固定湊方案數量。交代修改前後、影響功能與副作用，還原會失去既定需求時不得視為等價解法。
- 區分避開本次觸發條件與消除缺陷，標明各方案已存在或尚待實作；現況已符合目標就驗證，不重複異動。某情境已正常，不能據此宣稱其他分支也已修好。

## SQL 撰寫原則

- **KISS**：採最簡單易讀的語句，只有實際需要時才使用變數、CTE、暫存表、動態 SQL 或控制流程。
- **DRY**：容易不一致的重複鍵值／條件用簡單參數或適當共用方式維持一致；不重做同目的查核，也不為少量重複增加抽象。保留更新前資料預覽與更新後結果驗證，避免都寫成相同筆數條件的中止判斷。
- **YAGNI**：只處理本次確認的資料、欄位、期間與驗收，不預做歷史回補或通用框架。
- **筆數檢查**：預覽顯示範圍與預期筆數；正式異動保留完整 WHERE 與實際影響筆數檢查。在交易可回復且沒有其他副作用時，不再增加相同預期筆數的前置中止判斷；前置檢查只在防護不同業務前提或避免不可回復副作用時保留。

精簡不省略必要 WHERE 範圍、影響筆數檢查、異動欄位及唯讀驗證；交易與回復措施依實際風險保留。註解及自訂提示用繁體中文。

### 範本與個案 SQL

- 維運手冊保存共用 SQL 範本，工作卡保存由該範本產生的完整個案版本；共用邏輯保持一致，個案只替換參數區。需要調整邏輯時，在手冊維護授權內同步更新範本並重新產生個案版本；無維護權限時明列差異與適用限制，不宣稱已同步。
- 本案已確認的人員、群組及其他業務參數預填，並簡述必要取值依據；尚未取得的必要參數須提供取得方式，查詢 SQL 與結果對應依[手冊格式](handbook-workflow.md#人工與-ai-共用格式)。執行者識別碼的填法／查法及須本人決定的開關另說明，不代填尚未確認的身分或同意。
- 同卡提供完整操作與驗證 SQL、執行順序及預期／實際結果；跨資料庫時按目標資料庫分段。手冊連結只作來源，不要求執行者跨頁尋找或拼接 SQL；本案執行前仍需取值的查詢亦放同卡。只保留執行與驗證需要的區塊，不堆疊舊方案。
- 共用異動範本與個案版本均遵循下列執行開關規則，預設唯讀；取得或預填參數不代表核准或寫入授權。

### 異動 SQL 的執行開關

- 所有會異動資料、結構或持久狀態的個案 SQL 都必須提供明確的執行參數，包含 INSERT、UPDATE、DELETE、MERGE、TRUNCATE、DDL，以及有副作用的程序／動態 SQL。SQL Server 使用 `DECLARE @Execute int = 0;`，先檢查 `@Execute IS NULL OR @Execute NOT IN (0, 1)` 並拒絕非法值；不要用 bit 自動將其他非零值轉為 1。其他引擎採該客戶端可執行的等效參數，不能只寫在註解中。
- **預設只檢查**：參數為 0 時，只做必要的唯讀查詢，顯示目標範圍、目前值、預計修改值（刪除則顯示待刪資料）及預期影響筆數，隨即結束或跳過全部異動分支；不執行 DML、DDL 或有副作用的程序，不以「先異動再 ROLLBACK」模擬只檢查。
- **明確切換才執行**：只有參數為 1 才進入異動分支並提交；NULL、缺值或非法值停止，不默認正式執行。所有異動語句都受同一參數保護，不能只保護 COMMIT 或漏掉後續步驟。
- 兩種模式沿用相同定位鍵、期間、必要條件與舊值，避免預覽與實際範圍不同。正式執行須重新核對前提，資料異動檢查實際影響筆數，結構異動核對目標物件及變更結果，保留異動後驗證；交易與失敗回復依引擎及副作用設計，不可回復的操作不得宣稱能靠 ROLLBACK 還原。
- 在同卡說明參數的 0／1 意義、預期筆數與執行條件。交付前檢查預設路徑不會到達任何異動語句；切換參數不取代 DB 寫入授權，純唯讀查詢不需此開關。

## 涉及程式／資料庫變更的交付

- **資料修正**：在同卡對應明細先用條列逐點交代資料表／定位鍵、欄位修改前後值及必要條件，一點一件事；依需要補充影響筆數、異動人員／時間欄位及待填值，接著放完整修正與驗證 SQL。
- **SQL 優先**：需修改 DB 的方案須提供可執行的修正與驗證 SQL，包含 View／程序定義變更，不能只描述做法或只給前端替代。核對當次原始碼、schema、約束與副作用後，限定業務鍵、期間及舊值；定義變更限必要欄位／分支，不以舊版整份覆蓋無關調整。缺少必要資訊先補核對，不猜語法；只有 SQL 無法維持必要業務規則／副作用或使用者指定時，才說明原因並提供具體畫面／API 替代，不能因已有 API 就取代 SQL。
- **替代操作**：提供入口、Method／路徑、關鍵傳值與預期結果；整筆覆寫時須先讀原設定並保留其餘值。不附未採用方案的 API 清單。
- **程式修正**：列實際修改的 repository 相對檔案／方法、改前改後及影響；不列只供追查的程式路徑。
- **驗收**：寫明必要環境、設定位置、操作順序、輸入與可觀察的預期結果。涉及隔離、相容或負向情境時保留相關案例；同版本同環境已確認的相同結果不要求重跑。SQL 檢查分支、實際異動及人工驗收的結果分開記錄，預覽通過不代表異動分支已驗證。

個案 SQL 以可直接複製的程式碼區塊保存在同卡，不另建 `.sql`、交付／驗收文件、診斷 JSON 或目錄；共用邏輯須符合[手冊收錄門檻](handbook-workflow.md#收尾時新增更新或略過)才收錄於維運手冊，不另存個案交付檔。使用者明確要求匯出才另存。既有產品 SQL／遷移檔的實作修改依開發授權處理，不為個案交付另建副本。提供 SQL 不代表已執行，實際 DB 寫入仍須明確授權。

## 按需結構化報告

只有使用者要求完整 JSON 才用 [diagnosis.schema.json](../schemas/diagnosis.schema.json)。`solution_steps` 記同卡連結／明細、操作及預期結果，`test_results` 記實際證據，`user_reply` 遵循上述聊天格式；`changed_files` 只列實際異動，只有 Notion／SQL 內容交付時填 `[]`。未知文字填「尚未確認」，清單用 `[]`；系統未知時名稱／ID 用空字串。

分類為 USAGE_ERROR／CODE_BUG／FEATURE_REQUEST／UNKNOWN，影響為 TARGET_SYSTEM／SHARED_COMPONENT／UNDETERMINED；只有實際越出可存取或授權範圍才用 OUT_OF_SCOPE。未驗證修復用 PROPOSED_FIX／NEEDS_INFO，不用 FIXED。Schema／範圍工具只能檢查格式與聲明一致性，不能證明業務結果；操作見 [可選工具](repository-workflow.md#可選檢查工具)。
