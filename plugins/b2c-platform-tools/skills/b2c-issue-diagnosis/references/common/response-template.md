# 診斷交付

## 聊天與工作卡

聊天預設只寫簡短結論、實際處理狀態、必要的使用者動作及 Notion 同卡連結。完整修正、SQL、查核與驗收留同卡；只有使用者要求展開或 Notion 無法同步時，才在對話補充必要內容並如實說明未同步部分，不另存檔案備援。

診斷開頭先讓讀者看懂哪裡錯、正確應如何，以及影響或觸發條件；必要證據與限制緊接相關結論，不讓讀者從查核過程自行找原因。Git 引入時間與 commit 連結整併在原因說明；完整時間線只在比較版本會影響判斷時保留。

工作卡每段都檢查「刪除後是否影響判斷、修改、執行或驗收」；不影響就省略。必要因果用一句話交代，不列主機／資料庫名稱、精確查詢時間、無關關聯筆數、共同欄位或完整取值鏈路；只有這些差異確實影響處理或使用者要求追查時才展開。工具阻礙在聊天說明，卡片只列需使用者處理的動作與影響，不堆疊保留語。

程式已核對、現場查詢、使用者確認及假說必須分清楚；只保留本案必要證據與限制。Notion 的結構、色彩、圖片與人工結案統一依 [工作追蹤](notion-workflow.md)，不另套報告欄位。

## SQL 撰寫原則

- **KISS**：採最簡單易讀的語句，只有實際需要時才使用變數、CTE、暫存表、動態 SQL 或控制流程。
- **DRY**：容易不一致的重複鍵值／條件用簡單參數或適當共用方式維持一致；不重做同目的查核，也不為少量重複增加抽象。保留更新前資料預覽與更新後結果驗證，避免都寫成相同筆數條件的中止判斷。
- **YAGNI**：只處理本次確認的資料、欄位、期間與驗收，不預做歷史回補或通用框架。
- **筆數檢查**：預覽顯示範圍與預期筆數；正式異動保留完整 WHERE 與實際影響筆數檢查。在交易可回復且沒有其他副作用時，不再增加相同預期筆數的前置中止判斷；前置檢查只在防護不同業務前提或避免不可回復副作用時保留。

精簡不省略必要 WHERE 範圍、影響筆數檢查、異動欄位及唯讀驗證；交易與回復措施依實際風險保留。註解及自訂提示用繁體中文。

### 異動 SQL 的執行開關

- 所有會異動資料、結構或持久狀態的個案 SQL 都必須提供明確的執行參數，包含 INSERT、UPDATE、DELETE、MERGE、TRUNCATE、DDL，以及有副作用的程序／動態 SQL。SQL Server 使用 `DECLARE @Execute int = 0;`，先檢查 `@Execute IS NULL OR @Execute NOT IN (0, 1)` 並拒絕非法值；不要用 bit 自動將其他非零值轉為 1。其他引擎採該客戶端可執行的等效參數，不能只寫在註解中。
- **預設只檢查**：參數為 0 時，只做必要的唯讀查詢，顯示目標範圍、目前值、預計修改值（刪除則顯示待刪資料）及預期影響筆數，隨即結束或跳過全部異動分支；不執行 DML、DDL 或有副作用的程序，不以「先異動再 ROLLBACK」模擬只檢查。
- **明確切換才執行**：只有參數為 1 才進入異動分支並提交；NULL、缺值或非法值停止，不默認正式執行。所有異動語句都受同一參數保護，不能只保護 COMMIT 或漏掉後續步驟。
- 兩種模式沿用相同定位鍵、期間、必要條件與舊值，避免預覽與實際範圍不同。正式執行須重新核對前提，資料異動檢查實際影響筆數，結構異動核對目標物件及變更結果，保留異動後驗證；交易與失敗回復依引擎及副作用設計，不可回復的操作不得宣稱能靠 ROLLBACK 還原。
- 在同卡說明參數的 0／1 意義、預期筆數與執行條件。交付前檢查預設路徑不會到達任何異動語句；切換參數不取代 DB 寫入授權，純唯讀查詢不需此開關。

## 涉及程式／資料庫變更的交付

- **資料修正**：在同卡對應明細先用條列逐點交代資料表／定位鍵、欄位修改前後值及必要條件，一點一件事；依需要補充影響筆數、異動人員／時間欄位及待填值，接著放完整修正與驗證 SQL。
- **SQL 優先**：核對當次原始碼、schema、約束與副作用後，限定業務鍵、期間及舊值，保留其他欄位。缺少必要資訊先補核對，不猜語法；只有 SQL 無法維持必要業務規則／副作用或使用者指定時，才說明原因並提供具體畫面／API 替代，不能因已有 API 就取代 SQL。
- **替代操作**：提供入口、Method／路徑、關鍵傳值與預期結果；整筆覆寫時須先讀原設定並保留其餘值。不附未採用方案的 API 清單。
- **程式修正**：列實際修改的 repository 相對檔案／方法、改前改後及影響；不列只供追查的程式路徑。
- **驗收**：寫明必要環境、設定位置、操作順序、輸入與可觀察的預期結果。涉及隔離、相容或負向情境時保留相關案例；同版本同環境已確認的相同結果不要求重跑。

個案 SQL 以可直接複製的程式碼區塊保存在同卡，不另建 `.sql`、交付／驗收文件、診斷 JSON 或目錄；即使可重用亦同。使用者明確要求匯出才另存。既有產品 SQL／遷移檔的實作修改依開發授權處理，不為個案交付另建副本。提供 SQL 不代表已執行，實際 DB 寫入仍須明確授權。

## 按需結構化報告

只有使用者要求完整 JSON 才用 [diagnosis.schema.json](../schemas/diagnosis.schema.json)。`solution_steps` 記同卡連結／明細、操作及預期結果，`test_results` 記實際證據，`user_reply` 遵循上述聊天格式；`changed_files` 只列實際異動，只有 Notion／SQL 內容交付時填 `[]`。未知文字填「尚未確認」，清單用 `[]`；系統未知時名稱／ID 用空字串。

分類為 USAGE_ERROR／CODE_BUG／FEATURE_REQUEST／UNKNOWN，影響為 TARGET_SYSTEM／SHARED_COMPONENT／UNDETERMINED；只有實際越出可存取或授權範圍才用 OUT_OF_SCOPE。未驗證修復用 PROPOSED_FIX／NEEDS_INFO，不用 FIXED。Schema／範圍工具只能檢查格式與聲明一致性，不能證明業務結果；操作見 [可選工具](repository-workflow.md#可選檢查工具)。
