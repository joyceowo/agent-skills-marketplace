# 系統知識維護

以繁體中文整理可供下次診斷使用的系統理解。僅在使用者明確要求整理或維護系統知識時執行；問題診斷完成後不自動觸發。入口技能保留既有識別碼，各系統目的地讀其專屬資料，不在共用流程硬編碼。

## 適用時機

- 使用者明確要求知識整理後，沿用已確認的系統、來源與目的地，繼續必要查閱與維護。
- 單純診斷、開發、工作卡更新或驗收不觸發知識維護，也不在工作卡新增知識頁導覽。

## 保存內容

只整理會幫助後續理解、判斷或排查的內容，不逐案抄寫程式與工具輸出：

- 業務規則與名詞：意義、適用條件、計算規則、例外及不適用情況。
- 流程：角色、操作順序、狀態轉換、主要驗證與失敗處理；跨方法／模組的流程可用精簡圖說明。
- 資料關係：來源、關聯鍵、資料流向、更新／覆寫與隔離範圍，指出跨表或跨系統的影響。
- 設計原因與約定：決策理由、相容需求、歷史限制與取捨；程式行為本身不能證明設計者的動機。
- 共用相依與排查經驗：哪些使用者受影響、有效檢查入口、可重做的驗證方式，以及必要的系統名稱／別名與入口索引。

## 隨附索引的取捨

- 已有文件、API 或檔案線索時直接讀相關來源；需要找入口才讀功能索引，不要求每案先讀完整系統資料。
- 每個已盤點模組保留名稱／別名、問題關鍵字與現有來源；B2C 使用 `<模組>/index.md` 作單一精簡入口，主功能表只放連結與狀態。有可定位資料才建立，不以空檔表示盤點完成。
- 入口聚焦既有文件、前後端程式、共用相依／中介、驗證線索與未確認限制。特殊規則只記會改變判斷的差異並附來源；內容長到不易查閱才拆參考，不要求固定的 scope／knowledge 檔名或成對建立。完整 API／欄位／方法清單直接查 Controller、Model 或原文件。
- 通用診斷、授權、SQL 與交付要求引用共用流程；完整業務文件及個案歷程沿用既有 repository／Notion 來源，避免複製。精簡時保留唯一的已確認規則與必要風險，直到有可追溯來源承接。
- 同一資訊選定一處維護，其餘用連結導向；核對日期與適用版本集中記錄，依本案需要核對，不要求全量重建。

## 知識依據

每個會影響判斷的結論標示依據與適用範圍，格式依內容決定，不要求建立固定資料庫欄位：

| 標示 | 保存依據與限制 |
| --- | --- |
| 程式已核對 | 提供當次讀取的 repository 相對檔案、類別／方法或資料關係，說明實作與條件；讀碼不等於已執行、已部署或業務已認可。實測結果另註執行方式與限制。 |
| 使用者已確認 | 連到明確需求、決策或已確認工作卡／對話內容，簡述確認事項；不能由預選、推薦、未回覆或助手推斷產生。 |
| 待確認推測 | 說明支持線索、假說及尚缺的證據／驗證，獨立於已確認規則；下次不得當成既定需求或實作事實。 |

同一結論可同時具備前兩項標示；確認範圍不同時分開寫。使用者需求與程式不同時，分別保存「使用者已確認的預期」及「程式已核對的現況」，連結差異，不用任一方覆蓋另一方。推測取得證據後才更新相應標示；規則變更保留影響判斷的歷史與生效條件，未提供的日期不捏造。

## 存放與更新權限

- 先從本次系統資料解析適用的知識目的地預設，沿用已確認的頁面／父位置；沒有專屬預設時才釐清位置。一般診斷不因存在目的地就自動建立或更新知識頁。
- 日常累積的知識以該使用者已確認、可存取且可編輯的 Notion 系統知識頁為主；工作卡保存個案歷程，知識頁保存跨案件可重用的結論，互相連結，不把整張工單複製到知識頁。
- 沿用已確認的系統知識頁或允許建立知識頁的父頁／專案位置。尚無頁面但父頁與建立權限已確認時，可在該處建立一張系統知識頁並保留連結；沒有專屬預設的其他系統，僅知道工作看板不代表知識目的地已確認；所有系統均不可把知識頁當成工單建入工作看板。
- 無適用預設的系統，寫入位置仍不明且有知識需保存時，依診斷 Skill 的 [提問卡片規則](../../SKILL.md) 詢問一次；答案送出前不寫入，不阻擋不依賴位置的工作。有位置但無編輯權／工具失敗時回報尚未同步，不擅自換目的地、權限或改寫其他人的頁面。
- 每位安裝者使用自己的 Notion 連接與經確認的目的地；多人共用經確認的知識頁時，有相應權限的人可更新，不需要擁有外掛原始碼權限。頁面沿用 Notion 的權限，不因技能可用就宣稱遠端可寫。
- Skill 套件保存通用流程與隨版本分發的參考／索引。一般診斷及知識維護不修改安裝快取、marketplace 原始碼或其他安裝者設定，也不把個人知識／Notion 位置寫入共用外掛。只有使用者明確要求維護外掛來源且具寫入權限時，才更新適合分享的隨附參考並走既有發布流程。
- 知識維護不要求先設定本機路徑；只有需要讀前後端程式時依 [初始化與缺項詢問](initialization.md) 解析對應路徑。本機路徑與 Blob 來源設定不另存個案或知識快照。使用者明確指定其他持久位置時依該授權處理，沒有可寫目的地就清楚回報待保存內容，不宣稱已學習或已同步。

## 維護流程

1. 從本次證據判斷值得保存的差異；先讀已確認範圍內的系統知識頁，確認系統與現有結論。系統知識頁與候選工作卡分開；不藉知識整理擴讀尚未確認或已完成工作卡，沿用 [Notion 工作追蹤](notion-workflow.md) 的卡片確認限制。
2. 對照同一規則／流程／資料關係，最小幅度新增、修正或標記過期內容；保存依據、條件與必要的來源連結。已存在且無差異的結論不追加重複紀錄，不把推測升格為確認。
3. 寫入前核對頁面最新內容與實際結構，保留他人資料、人工勾選與歷史；有新衝突先處理差異，不覆寫整頁或自行新增資料庫欄位。既有頁面被刪除時回報，不擅自重建。
4. 以工具實際回傳判斷成功；有警告或部分失敗就查明並回報。知識頁連結與本次已保存／尚未同步的範圍併入這次知識維護的回覆，不能把工具受理、推測或未寫入內容標成完成。

可選的程式範圍工具見 [範圍檢查](../../../b2c-system-maintenance/references/configuration.md)；它不代替知識整理或 Notion 權限。業務程式、測試與 SQL 留原 repository，不自動執行 SQL、部署、發送訊息或 Commit。瀏覽器先用內部瀏覽器，確定無法使用才詢問 Chrome。
